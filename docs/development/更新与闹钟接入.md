# 更新与闹钟接入

本文针对 `D:\OpenAgentAtelier` 提纯版本。更新框架和闹钟运行时已移植，角色身份、包名和资源仍按本项目的导入模型体系管理。

## 独立更新配置

默认构建没有更新来源，`UpdateRuntime.production()` 返回 `disabled/not_configured`，不会连接旧项目 stable，也不会自动调用安装器。Android application ID 保持 `com.ateleragent.studio`；Windows `ProductName=AgentAtelier` 继续承担既有本地数据路径身份，显示名称 / EXE 使用 `OpenAgentAtelier`。

本项目仅读取 `OAA_UPDATE_CONFIG_BLOB` / `OAA_UPDATE_CONFIG_KEY`，加密配置的 pack ID 为 `open-agent-atelier-update-config-v1`。旧项目的 `AAR_UPDATE_CONFIG_*` 定义和配置密文不会被自动接受。构建脚本不自动寻找 `.asset_protection/update_server.json`，只有显式传入 `-UpdateConfigDefinesPath` 才注入更新定义。

在被忽略的 `.asset_protection/` 内准备本项目自己的 JSON。以下是结构示例，示例地址不会提供服务，公钥占位符必须替换为独立发布系统的 Ed25519 **公钥**：

```json
{
  "v": 1,
  "github_latest_url": "https://updates.example.test/openagentatelier/latest.json",
  "trusted_keys": {"openagentatelier-release-1": "<32字节公钥的标准Base64>"},
  "resource_asset_key_ids": ["openagentatelier-resources-v1"],
  "release_seq": 1,
  "channel": "openagentatelier-stable",
  "runtime_compat_id": "openagentatelier-android-bootstrap-v1",
  "resource_api_version": 1,
  "updater_protocol_version": 1
}
```

可选镜像字段为 `gitee_latest_url`、`cache_latest_url`；至少有一个有效 HTTPS 来源。发布序列和兼容 ID 必须由本项目独立维护，不能复用原项目的发行序列、信任公钥或资源快照。`resource_asset_key_ids` 是资源兼容标识，并非实际密钥；用户导入模型和本地闹钟音频不通过此更新通道替换。使用受保护 `.aarpack` 的更新需额外配置对应资源解密支持，纯导入模型构建没有原版角色资源密钥。

生成定义文件只做本地解析、校验和加密，不访问服务器、不构建 APK：

```powershell
dart run tool/prepare_update_config.dart `
  --config-file .asset_protection/openagentatelier-update.json `
  --output-file .asset_protection/openagentatelier-update.defines.json
```

需要构建时，仍使用保护脚本；以下命令仅作接入说明，本次迁移未执行构建或安装：

```powershell
.\tool\build_protected.ps1 -Target apk -Mode release `
  -UpdateConfigDefinesPath .asset_protection/openagentatelier-update.defines.json

.\tool\run_protected.ps1 -Device emulator-5554 `
  -UpdateConfigDefinesPath .asset_protection/openagentatelier-update.defines.json
```

两个脚本在执行依赖解析前验证该文件恰好只含两个 OAA 更新字段及编码字符串。额外字段、旧 AAR 字段、数组、重复字段或空值会被拒绝。运行时还会验证密文、严格 JSON、可信签名、通道、平台、发布序列、包名、ABI、证书和内容哈希；安装阶段由 Android 展示确认界面。

桌面使用完整包更新。`DesktopUpdatesPage` 在未配置时禁用发布页按钮；宿主可传 `releasePage: Uri`，或单独通过 `OAA_DESKTOP_RELEASE_URL` 设置自己的 HTTPS 发布页。此字段不是 Android 的更新配置，不能放入上述只接受两个字段的定义文件。Windows 更新时保留完整 EXE、DLL 和 `data/`，本地用户数据继续留在稳定的数据目录。

## 宿主和资源接口

`lib/src/update/` 包括签名清单验证、更新规划、可恢复下载、SHA-256 检查、资源快照激活与回滚、安装权限、更新中心和前台提示。应用 bootstrap 调用 `UpdateRuntime.production()` 并负责 `dispose()`；没有配置时不会启用网络来源。

- `ResourceOverlayAssetBundle` 放在 `DefaultAssetBundle` 中；受管理资源由 `ResourceAssetResolver` 返回已验证文件，失败回退到随包资源。
- `UpdateForegroundHost(runtime:, dialogCoordinator:, language:)` 放在 Navigator 下。`RelayForegroundHost` 使用同一个 `ForegroundDialogCoordinator`，PC 请求可抢占可选更新提示。
- `ProductionResourceHealthValidator` 通过 `ProtectedAssetRuntimeCache.ensureValidated()` 缓存内容校验结果；该缓存不替代下载文件哈希与清单签名检查。
- `ApkUpdateInstaller` 通过 `agent_atelier_r/apk_update_installer` 调用 `ApkUpdateBridge`。历史 channel 名只是稳定协议 ID，不是显示品牌或数据共享许可。原生校验更新 APK 必须属于当前应用，拒绝其它包名、错误签名、错误摘要和降级。

Android Manifest 增加受限 FileProvider、`REQUEST_INSTALL_PACKAGES` 与更新路径 XML；没有更新配置时运行时不会申请安装权限或打开安装器。声明权限本身不会触发安装。

## 导入模型闹钟

闹钟页面先要求选择已导入模型，再让用户选取本地提醒音频。支持扩展名 `mp3/m4a/wav/ogg/aac/flac`，文件大小必须在 1 字节至 64 MB；实际可播放编码取决于系统。`ModelAlarmAudioStore` 使用文件选择器的字节 API，兼容 Android SAF，并复制到本应用支持目录 `model_alarm_audio_v1/<编码后的模型ID>/`。模型之间不共享默认声音，不读取旧游戏语音目录。

每个模型使用独立设置键 `model_alarm_audio_v1:<编码后的模型ID>`。`CharacterAlarmCoordinator.payloadForModel(modelId)` 生成 `character:model:<modelId>`，`syncForCharacter('model:<modelId>')` 暂停其它模型闹钟并恢复当前模型未过期的闹钟。`model:null`、`model:pending` 或旧角色别名不恢复任何模型闹钟；历史游戏语音只会暂停。

暂停前先持久化快照；原生停止失败时保留可重试状态，阻止另一个模型闹钟提前恢复。更换提醒音频后，旧文件保留供已有闹钟继续使用。提醒音频设置属于本设备应用数据，当前不会随模型 ZIP 导出；迁移到新设备后应重新选择音频。

`AlarmRingingOverlay(enabled:, language:, child:)` 放在 `MaterialApp.builder` 的最外层，确保对话框和虚拟手机页面无法遮住唯一停止按钮。它按原生实际响铃状态展示，支持停止一个 / 全部闹钟、恢复前台重新查询、失败保留按钮并允许重试。

Android 原生 `.AlarmRingingActivity` 在锁屏之上提供无需启动 Flutter 的停止入口。`packages/alarm_android` 已有的 RING action、重叠闹钟、通知停止和来电策略继续复用；停止后等服务报告真正停止，再结束或切换到下一个响铃闹钟。应用进入设置页并非停止响铃的必要条件。

实时语音新增 `RealtimePcmBridge` 和录音权限；它沿用 `CallAudioGuard`，原生来电或闹钟接管音频时中断 PCM 播放。原有 `Spine36Bridge`、模型名称通知同步和 MCP callback 保留。
