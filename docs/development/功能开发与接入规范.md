# OpenAgentAtelier 功能开发与接入规范

本文面向修改当前提纯版的开发者，源码根目录为 `D:\OpenAgentAtelier`。依据当前 Dart、Android、Windows 实现整理；文件中的既有英文类型名、存储键和协议名不等于产品显示名。应用显示名统一为 **OpenAgentAtelier**，人物名称、头像、加载提示和对话身份应来自当前选择的模型。

文中“已实现”指仓库中已有对应调用链，不代表本次已执行真实服务请求或完成设备视觉验收。“扩展步骤”是开发要求，不是已经存在的插件 API。当前没有统一的 `registerPlugin`、`registerRenderer` 或动态安装功能模块的注册中心；新增能力需要显式修改相关枚举、适配器、路由和校验分支。

2026-10-24 增补功能的范围与验证见 [主项目新增功能移植说明](主项目新增功能移植说明.md)；语音和平台桥接详见 [实时通话与语音接入](实时通话与语音接入.md)，独立更新与提醒音频详见 [更新与闹钟接入](更新与闹钟接入.md)。人格、生图、戒指及玻璃界面接入见本文第 18 节。

## 2. 当前人物身份和技术兼容 ID

### 2.1 显示身份以当前模型为准

`AppController` 提供以下不同用途的数据，不能互相代用：

| 符号 | 用途 |
| --- | --- |
| `activeModelId` | 当前导入条目的稳定 ID；不同导入条目拥有独立资料 |
| `activeModelDisplayName` | 用户可编辑的当前人物显示名 |
| `activeCharacterProfile` | 当前展示使用的名称与资源资料；导入模型使用中性模型档案 |
| `activeConversationScopeId` | 当前会话范围；有模型时使用模型 ID，否则保留兼容范围 |
| `activeCharacterId` | 既有存储归属与协议兼容字段，不是给新人物取名的入口 |
| `dataRevision` | 切模型、读档和导入等操作使旧异步结果失效的版本标记 |
| `usesBuiltInCharacterWorld` | 旧世界能力的事实门控，不能用显示名或文件名代替 |

新增人物文本、通知、头像或加载界面时，从控制器/当前 `CharacterAppearance` 取值，并监听模型切换。名称为“晨星”的模型不能因为技术归属字段为 `ryza` 就显示另一个人物的名字、立绘或预设音色。没有导入模型、预览缺失或恢复失败时，显示中性人物图标、占位和明确的导入提示。

`CharacterRuntimeIds.ryza` / `sophie`、`ChatSpeaker.ryza`、`RyzaPerformanceSegment`、现有包内 owner 字段、旧数据转换规则等仍具有兼容用途。它们不能用全局文本替换改成任意新模型名，也不能将每个模型 ID 添加到旧人物枚举中。新增动态人物走模型库和模型档案。

### 2.2 产品名与存储身份分开修改

对用户可见的应用标题、窗口、EXE 和显示描述使用 OpenAgentAtelier。Dart 可见品牌统一读取 [app_identity.dart](../../lib/src/app_identity.dart) 的 `appDisplayName`；当前启动流程已移除固定品牌 Logo 的三秒覆盖层，人物加载界面继续跟随当前模型。Android `applicationId` 继续为 `com.ateleragent.studio`，Fish OAuth 回调继续为 `agentatelier-fishmcp://oauth/callback`。现有 MethodChannel 名称也是桥接契约，产品改名不要求改桥接名。

Windows `Runner.rc` 的 `ProductName=AgentAtelier` 和公司 `com.ateleragent` 保留为 `path_provider` / `shared_preferences` 的存储身份；修改它会影响现有数据查找。它与可见的 `FileDescription`、窗口标题、可执行文件名分开维护。若未来确需换数据目录，应实现显式迁移并验证回滚，而不是只改字符串。

## 3. 状态、生命周期与异步结果

### 3.1 状态归属

- 共享业务状态写入 `AppController`；页面的展开、滚动、输入草稿和当前路由等短期交互留在 Widget State。
- 模型人物资料、聊天、记忆、状态和存档归当前模型；AI/TTS 服务连接、鉴权、设备权限、音量和界面偏好属于设备。字段的实际可迁移范围以 `ModelPackageStore.sessionDataKeys` / `sessionPreferenceKeys` 为准。
- 收藏通过 `ConversationCollectionStore.open(characterId: ..., modelId: ...)` 隔离；它有独立导出流程，不能当作模型 ZIP 已经包含的内容。
- `AppController` 的 setter 通常通过 `_changed()` 通知与排队持久化。新增字段必须同时检查初始值、加载、setter、导出、导入、模型切换和旧版缺字段的默认行为，不能只给 UI 加一个开关。

`_saveInProgress` / `_saveAgain` / `_saveDrain` 合并连续保存；模型切换使用 `_modelSwitchTail` 串行；本地存档写入也有独立串行链。需要可移交的持久结果时调用并等待 `flushModelSession()`，不要把 `notifyListeners()` 或一个未等待的保存 Future 当成写入完成。

### 3.2 所有异步入口都需要失效条件

主聊天已有 `_replyGeneration`、`_speechPlaybackGeneration`、`_suggestionGeneration` 和 `StreamIterator.cancel()`；模型加载有 `_loadGeneration`；记忆有 `MemoryRefreshGate`；ASMR 有 `_generation` 与 `_sessionScope`。新增网络请求或原生回调应沿用所属模块的规则。

一个可借鉴的宿主页写法如下，`result` 只有在原范围仍有效时才能提交：

```dart
final modelId = controller.activeModelId;
final revision = controller.dataRevision;
final result = await operation(); // 功能自己的可取消操作
if (!mounted ||
    controller.activeModelId != modelId ||
    controller.dataRevision != revision) {
  return;
}
// 在这里通过该功能的 controller / Store 接口提交 result。
```

这只是结果归属检查，不会自动中断 HTTP，也不代表原操作没有副作用。已发出的付费生成、PC 操作等必须另外处理结果未知与幂等性。`Future.timeout` 本身也不会关闭底层请求；模型映射的超时会关闭专用 `http.Client`，`PlanningHttpClient` 使用 `AbortableRequest` 和定时器中断可选规划，不能只丢弃 Future 后继续堆积请求。

### 3.3 页面和资源释放

`AppShell.didChangeAppLifecycleState` 在离开前台时触发 `flushModelSession`、清理触摸活动，并同步 relay 前台状态；回前台重设帧率、人物通知和声景。后台陪伴停止事件与“取消聊天回复”是不同状态，不能混为一谈。

新增页面须对称处理 `addListener/removeListener`、观察者、StreamSubscription、Timer、AnimationController 和音频/原生资源。关闭虚拟手机、切换人物、快速读档、旧请求晚返回都必须纳入验证。底层单例的生命周期不应由一个短命子页面随意 `dispose`。

## 4. 聊天、LLM、翻译和上下文

### 4.1 已实现调用链

```text
ChatScreen._sendMessage
  → AppController：用户消息、流式占位、buildCharacterPrompt、contextMessagesForModel
  → SecretStore.readLlmKey(provider, openAiSlot: ...)
  → OpenAiCompatibleClient.streamChat
       ├─ OpenAI 兼容：chat/completions + SSE
       ├─ Agent：工具轮次 + 工具结果回放，再完成正文
       └─ Gemini：原生 interactions + 事件解析 / function_result
  → appendAssistantDelta
  → 语言校验 / 按设置处理翻译
  → replaceAssistantStreamText / finishAssistantStream / completeLlmDialogueTurn
  → 可选：近期/长期记忆、状态结算、语音规划、动作表情规划、TTS
```

`OpenAiCompatibleClient.streamChat` 返回 `Stream<String>`，消费者收到的是正文增量。Agent 工具阶段会使用非流式完整消息完成工具调用，并不保证每个阶段都有逐 token 的可见正文。OpenAI 的 `reasoning_content` / `reasoning_details` 仅在工具历史需要时回放，不能作为人物台词、记忆或 TTS 输入。

OpenAI 请求通过 `_chatBody`、`_streamRequest`、`_completeMessage` 构造和读取；终止标记、空 choices 的 usage 块、错误对象和非成功状态都需要保留处理。`_messageContent` 统一处理消息附件，不要在 UI 再拼一套不同的请求。

Gemini 在 `gemini_interactions.dart` 中以 `part of 'ai_services.dart'` 扩展同一客户端，使用 `/interactions`、`x-goog-api-key`、`system_instruction`、`input`、`store:false`。它不是 OpenAI 兼容路径，也不是 `generateContent` 路径。SSE 支持跨网络块与 EOF 收尾；工具回放保留服务端步骤和 thought signature。当前原生文档附件支持 PDF 和文本，图片走 image content，其他类型应给出转换提示。

### 4.2 改提示词或增加 LLM 服务商

1. 先检查 `AppController.buildCharacterPrompt` / `_buildCharacterPrompt` 和 `contextMessagesForModel`，确认人物/世界注入、上下文兼容开关、语言、近期/长期记忆、附件和当前模型身份从哪里进入。
2. 用户设定、世界书、历史、模型资源说明和附件均为不可信数据。保留系统边界及数据块结构；不要把用户文本直接提升为工具权限或系统指令。
3. 新服务商需显式修改 `LlmProvider` 的定义与引用、设置页面、设备配置读写、`SecretStore` 鉴权入口及客户端请求/响应分支。不存在自动读取任意服务商插件的机制。
4. 推理能力通过 [model_thinking.dart](../../lib/src/model_thinking.dart) 的识别与字段构造处理；不要向所有模型无条件发送同一个思考字段或输出预算。主聊天当前未启用 `outputMultiplier` 控制。
5. 辅助请求使用 `complete` 和 `AuxiliaryCompletion` 等已有接口，明确 `lightweight`、规划用途、超时与 token 预算，不能重新带入整段聊天或默认启用 Agent。
6. 验证 OpenAI 与 Gemini 两条路径的正文、工具、附件、错误、取消和 usage；不要只测一个兼容服务商就宣称另一条原生 API 已支持。

### 4.3 分段与翻译契约

[chat_segments.dart](../../lib/src/chat_segments.dart) 的 `parseAssistantSegments`、`ChatSegment` 和展示文本函数区分主角、旁白、其他人物与控制标签。旧 `ChatSpeaker.ryza` 表示既有的主角语义槽，不应作为 UI 显示身份。扩展说话人语法时，同时核对语音选择、收藏、翻译、上下文和记忆抽取。

语言校验在 [dialogue_language_guard.dart](../../lib/src/dialogue_language_guard.dart)，翻译工具在 `auxiliary_llm_tasks.dart`。独立翻译异步完成时必须检查 `dataRevision`、消息和目标语言仍一致，避免把旧模型或旧设置下的译文写入当前记录。译文、表演标签和对话正文不能互相覆盖。

## 5. 模型扫描、LLM 映射和审阅

### 5.1 已实现导入路径

`SkinImportControls._importZip` 选择 Spine / Live2D / VRM / 模型与数据 ZIP → `inspectModelResources` 本地扫描 → `ModelMappingReviewPage` 显示资源与兼容性 → 用户发起 `ModelMappingService.analyze` → 严格解析映射 → 用户确认 → 对应 Store 校验并提交。

导入模型与数据 ZIP 时，先用 `ModelPackageStore.decodePackage` 得到资源 ZIP 与应用快照，然后仍走扫描、映射和确认，不因包中有旧映射就跳过验证。单独的场景、座椅、替换贴图使用各自导入分支。

`ModelResourceCatalog` 保存 `format`、`sourceFingerprint`、`runtimeVersion`、`entryFile`、`resources`、`runtimeSupported`、`compatibilityIssues`、`existingMapping`。`resourceById` 是资源引用的事实查询入口，LLM 只看到资源目录/必要摘要，不会因此获得执行脚本或改写骨架的权限。

`toPromptJson` 默认 512 KiB UTF-8 预算，超出会明确报错，不静默截掉后半资源。`ModelMappingService` 默认分析超时 90 秒，可注入 `ModelMappingTransport` 用于测试。请求读取当前设备的 LLM 配置与安全存储密钥，映射结果不作为聊天或长期记忆保存。

### 5.2 schema v1 的硬契约

| 字段 | 规则 |
| --- | --- |
| `schemaVersion` | 必须为 1；未知顶层字段拒绝 |
| `sourceFingerprint` | 必须与本次扫描的原始资源指纹相同，不能跨模型复用 |
| `format` | 与目录格式精确相同 |
| `label` | 有界显示文本，不决定人物经历或世界设定 |
| `idle` | Spine 必须绑定实际 animation；Live2D/VRM 没有可靠资源时可为空 |
| `actions` | 每项包含 `target/description/confidence/evidence`；target 类型与格式匹配；自定义语义使用受限小写 slug，不能为 `none` |
| `expressions` | 语义来自 `CharacterExpression`；目标是当前模型可验证的 animation / expression |
| `parameters` | 语义来自 `supportedModelParameterRoles`；目标类型与当前格式一致 |
| `notes` | 记录无法确认或未绑定的能力，不用于冒充成功 |

完整解析入口为 [model_performance_mapping.dart](../../lib/src/model_performance_mapping.dart) 的 `ModelPerformanceMapping.parse/fromJson`；映射文本上限 128 KiB。`runtimeSupported` 由本地扫描器决定，不能接受 LLM 返回值替换它。

`mouthOpen` 必须有可连续控制闭口到张口的直接证据。普通循环说话动画不能当作 0..1 嘴部 scrub。资源名存在不等于语义视觉正确，用户仍需实际播放检查动作方向、幅度、表情和参数范围。

### 5.3 新增扫描格式或资源类型

这是扩展方案，当前无自动注册接口：

1. 为 `ModelResourceFormat` 增加显式值，并在 `inspectModelResources` 分支中实现解析、入口唯一性、版本、引用文件和兼容问题检查。
2. 使用稳定的 `ModelResourceKinds` / 资源 ID；指纹基于源文件计算，不把生成的映射文件反过来作为同一源指纹的一部分。
3. 同步映射 parser 对目标类型、语义、数量和文本大小的限制；修改 LLM system prompt 的 schema 说明。
4. 完成对应播放器和可见能力检查后，才把扫描结果设为运行支持。扫描成功不能直接等于可导入播放。
5. 在审阅页和导入 Store 增加明确分支，并验证取消/失败不会创建半个模型档案。
6. 增加恶意 ZIP、伪造指纹、跨模型引用、目录过大、版本不支持和真实运行资源缺失的测试。

## 6. Spine、Live2D 与 VRM 播放适配

| 格式 | 当前实现 | 不应承诺的能力 |
| --- | --- | --- |
| Spine 4.2 JSON / binary | 本地 `packages/spine_flutter`；通用映射由 `MappedSpineView` / `MappedSpineCapabilities` 执行，兼容模板由 `ChatScreen` 中的既有控制器结合 `CharacterSpineView` 承载 | 任意骨架自动拥有专用模板的骨骼偏移、触摸物理、姿态和动作组合 |
| Spine 3.6 JSON | `Spine36Model` / `Spine36Player`，Android 离线 WebGL 平台视图；`validate()` 使用同一运行库解析并绘制 | 3.6 binary、把版本字符串改成 4.2、其他平台已经可播放 |
| Live2D model3 | `LocalLive2dStore`、`Live2DModelDescriptor`、`CharacterLive2dView` → 本地 Cubism 插件 | `.cmo3` 工程直接播放；从动作编号猜手型；自动使用未声明参数 |
| VRM 0.x / 1.x | 扫描 `.vrm/.glb` humanoid / expression 元数据并生成映射；`runtimeSupported:false` | 当前不存在 VRM 播放器和可确认导入的完整链路 |

Spine 原始导入包当前要求单张图集 PNG、同基础名称 atlas 与 skel/JSON，ZIP 和展开内容各受 64 MiB 限制。3.6 判断使用 `isSpine36` 的精确版本规则，`spine36Available` 当前仅 Android。映射还会与运行时真正加载出的动画名核对。

`ModelPerformanceMapping.toSpineGesture` 生成 gesture 的 `ModelMapping.Runtime`，`runtimeFor` 指定 `generic_spine`。`MappedSpineCapabilities.parse` 再验证真实 idle/动作/表情/参数，动作组使用 `grp_mapped_*`。专用模板通过 `SpineControlTemplates` 匹配并检验基础动画，不能按相似文件名套用。

Live2D ZIP 必须只有一个 `.model3.json`，完整保留它引用的 moc3、贴图、动作、表情、物理和姿态；压缩/展开/单文件限制分别为 128/256/128 MiB。`toLive2dManifest` 生成 `performance.manifest.json`，完整映射另存 `performance.mapping.json`。`CharacterLive2dView` 用 `Live2DViewController` 串行下发原生命令，按 load generation 丢弃旧加载结果；缺少映射时保守不执行，不借用 Spine 候选。

Live2D 的 `grp_live2d_*` 只指本模型 motion；idle 必须对应真实 group/index，动作结束后恢复。只有绑定的嘴部参数接受语音振幅。`parameters` 中记录了 angle/gaze/breath 等角色不代表所有通用控制器都已经消费这些角色；增加控制器前须逐项证明接线和暂停/恢复行为。模型自带 motion `Sound` 不会自动变成另一路播放器。

扩展新渲染器时，保留统一的“语义 → 当前模型真实能力”边界。对无对应动作返回 `none/unsupported`；不要为看起来更丰富而选择无关动作。`IndependentPerformanceTools` 与 `ActionPlannerTool` 根据当前渲染器能力生成候选，新增能力须更新候选构造、结果验证和实际执行三处。

### 6.1 视线、IK、脸部与触摸物理的专用绑定边界

`CharacterCamera` 处理场景坐标逆变换、拖动、缩放与指针时间；[character_gaze.dart](../../lib/src/character_gaze.dart) 的 `CharacterBodyGaze` 只操作已有模板明确列出的控制骨/肩关节，部分 control 是模型已制作的 IK 目标，通过平移驱动已有约束，当前没有通用自动 IK 绑定器。root、髋、脚和手指仍由原姿态及约束管理，不应为追踪指针随意改写。

`CharacterFacePullRig` 对特定可识别的脸部网格做局部 deform，保护五官；`CharacterTouchPhysicsRig` 按 draw order、裁剪、贴图透明度和网格权重命中，再激励实际关联的原生物理约束。没有约束的区域不能凭空获得物理，触摸一处也不能激励远处无关部件。临时变形需先恢复再叠加当帧动画，暂停、切资源、读档、切后台要清理输入与旧异步掩码。

`ChatScreen._usesMappedSpine` 对通用映射模型隔离专用拖拽/触摸/视线链；新 Spine、Live2D 或未来 VRM 模型不会自动获得这套专用网格/骨骼驱动。需要扩展时，应先定义并验证该模型的骨骼、网格、坐标和约束能力，再实现对应适配与真实渲染验收。实现与原生回归入口见 [CHARACTER_FACE_PULL.md](../CHARACTER_FACE_PULL.md)；其中历史测试数量和旧模型效果记录不能当作当前导入模型的验收结论。

详见 [模型映射](../model_mapping.md)、[模型导入](../model_imports.md)、[Live2D 接入](../live2d_integration.md)、[本地运行库](../live2d_runtime_patch.md)。这些说明的历史表述发生冲突时，以当前代码和本规范的数据边界为准。

## 7. 模型独立档案、存档和 ZIP

### 7.1 切换与恢复

`AppController.setCharacterAppearance` 使用 `_modelSwitchTail` → `_selectCharacterAppearance` → 等待旧模型 `flushModelSession` → `_activateModelScope` → 校验/装载目标快照 → 增加 `dataRevision` → 应用目标会话。失败时恢复之前的内存状态，不能用空会话悄悄覆盖损坏包。

新资源导入创建新模型条目；不能仅以文件名覆盖已有聊天。新模型使用 `_freshModelData`，不会继承另一个模型的身份、关系或历史。旧版兼容迁移只作用于符合条件的那个当前模型，不把全局旧资料复制给库中每个模型。

名称修改走 `setModelDisplayName`，验证 1–256 字符并持久化，失败会回退。导出模型时先 `flushModelSession`，再 `ModelPackageStore.packageBytes`；恢复时使用 `restoreModelPackageData`，重绑定新条目的模型 ID，而不是直接把源包 ID 当成当前设备的新 ID。

### 7.2 持久包结构

```text
manifest.json                      # type=agent-atelier-model-package, version=1
model/...                          # 模型运行资源、预览、控制/语义映射
app/session.json                   # identity + 当前模型应用数据
app/save_slots.json                # 该模型存档槽和活动槽
app/attachments/texture.png         # 受支持的替换贴图附件
app/attachments/texture-state.json  # 贴图启用状态
```

`ModelPackageStore.ensureModel` 不允许已存在条目改变 owner 或 format。`saveSession`、`saveAttachments` 通过 `_serialize` 排队；更新会话复用原压缩模型资源，提交采用临时文件替换。`initialize` 遇到损坏包会保留原文件供恢复，不以空包覆盖。播放器展开目录是缓存，不能绕过模型 ZIP 维护一套互相矛盾的权威资源。

包格式限制：压缩包 256 MiB、展开总量 512 MiB、单模型文件 128 MiB、每个状态 JSON 32 MiB、最多 1024 项；具体运行格式可能有更小的导入限制。解包须检查路径规范、重复项、链接、CRC、模型资源 SHA-256 和大小，不接受任意 app 路径。内容校验是完整性验证，不是可信来源签名。

### 7.3 增加可随模型迁移的字段

1. 明确字段属于模型还是设备。人物音色 ID 可以属于模型；API Key、服务地址、OAuth、PC 配对 token、本地文件路径不能因此进入模型包。
2. 在 `AppController` 的人物会话导出/导入、`_freshModelData`、模型快照和相应 setter 中一致处理。
3. 在 `sessionDataKeys` 或 `sessionPreferenceKeys` 的相应层级加入白名单，并修改嵌套结构校验。未知字段不能靠“把整个 preferences Map 全塞进去”解决。
4. 核对 `saveToLocalSlot/createLocalSlot/loadFromLocalSlot/importLocalSlot` 等存档流程，以及 `_withDeviceSettings` 对设备配置的保留。
5. 验证 A/B 两模型切换、退出重启、导出换 ID 恢复、旧包缺字段、坏包拒绝与快速连续保存。

模型 ZIP 当前不携带聊天附件原件、收藏与收藏音频、临时 TTS、设备本地 TTS 模型/参考音频、壁纸、单独导入的场景/座椅、闹钟、主题和权限。不要把模型 ZIP、普通本地数据备份、单槽存档和收藏导出描述成同一种“完整备份”。详见 [模型档案与独立数据](../model_workspaces.md)。

## 8. 近期、长期与人工记忆整理

已实现三层协作，不能只改一个摘要提示词：

1. **确定性事实层**：`finishAssistantStream(recordMemory: true)` → `recordDeterministicMemoryForLastTurn` → `MemoryLedger.extractTurn`。保留来源消息 ID、角色、观察时间和分类；只记录有明确持久信号的完整断言，过滤问题、假设和未接受请求。
2. **近期摘要**：`ChatScreen._refreshLongTermMemory` 选择未整理对话 → `RecentMemoryConsolidator.consolidate` → `appendRecentMemory`。常规触发为至少四个用户轮次；有明确高信号内容时可提前，结果需匹配消息 checkpoint 和 `memoryEditRevision`。
3. **长期时间线**：`MemoryConsolidator` 合并近期摘要批次；当前自动流程检查八条待合并近期摘要。`memory_text.dart` / `memory_timeline.dart` 处理结构、去重与查询；写回必须通过控制器校验，不能只替换一段显示文字。

`MemoryRefreshGate.begin/owns/finish/invalidate` 防止旧请求释放新锁或在读档后回写；`MemoryBatchRetryCooldown` 使用批次内容、版本与范围构建身份，抑制同一失败批次的自动反复请求，人工重试和新会话保持可用。

人工整理使用 `ManualMemoryConsolidation.prepare` 产生 `ManualMemoryProposal`，经检查后由提案应用到 `AppController.applyReviewedMemory`。它校验版本、消息指纹、整理进度和人工编辑，避免覆盖用户刚改过的记忆或大量丢失旧条目。

上下文注入和 `search_memory` 使用 `memoryPromptForCurrentConversation` 按当前话题取相关资料。新增记忆类别时，核对抽取器、解析/归一化、检索、近期/长期合并、人工审阅、模型包和存档；不要把临时定位结果、工具鉴权或映射分析塞进长期人物记忆。

## 9. TTS、连续 ASMR、表演与口型

### 9.1 一条回复的语音链

`SpeechPlanner.plan` 只返回原台词位置上的情绪与 cue；`SpeechPlan.apply` 检查原分段、说话人、人物归属和原文是否仍匹配。它从不可变原文重建台词，不能让语音规划 LLM 改写剧情。cue offset 使用 UTF-16，并避开代理对；动作表情控制与发声标签分开。

`ChatScreen._playTtsIfConfigured` → 分段准备 `_prepareSpeech` → 相应客户端 → 标准化与解码 → 响度/时长/静音等检查 → `_playSpeechClip`。分段可以预取，但预取晚返回时必须检查 `_speechPlaybackGeneration`，取消后产生的临时文件要清理，不能在新一轮继续播出。

`TtsProvider` 目前显式包含：

| 值 | 客户端/条件 |
| --- | --- |
| `fishAudio` | `FishAudioClient`，REST Key + 音色 reference |
| `fishAudioMcp` | `FishMcpService`，OAuth 与已探测工具；普通 TTS 或 Studio 路由 |
| `dashScope` | `DashScopeTtsClient`，百炼 Qwen TTS，含对应定制音色流程 |
| `generic` | `GenericTtsClient`，通用 OpenAI TTS；供应商特定 instructions 不能无条件下发 |
| `mimo` | [mimo_tts_client.dart](../../lib/src/mimo_tts_client.dart)；单独配置与请求适配 |
| `local` | `LocalTtsClient` → Android CosyVoice 3；当前中文/日文，需本地模型与可用音色 |

新增 TTS 提供者要同步枚举、设置、SecretStore、请求/格式检测、普通/ASMR 音色选择、主聊天和连续 ASMR 两处合成分支。若有 NPC 语音分流，也要检查 `assistantSpeechTtsProvider` 及 reference 选择。不能把新提供者只接到预览按钮就称为全流程支持。

`speech_preparation.dart` 的 `SpeechRejectionBudget` 区分已明确返回的坏音频与计费未知错误，`TtsAudioQualityException` 表达质量拒绝；有效片段重置连续失败计数。`tts_duration_guard.dart`、`speech_preparation.dart`、`speech_loudness.dart` 的实际检查不应被 UI 成功提示绕过。

### 9.2 连续 ASMR

`ContinuousAsmrPage._start` 快照当前模型范围与配置，`prepareAsmrScript` 处理语言/分段，`_fillBuffer` 顺序生成并维持最多三个待播片段，`_play` 消费缓冲；翻译另行关联对应片段。`_stop` 先同步增加 generation 并唤醒等待者，再串行停止旧播放器，避免快速停开时旧 stop 把新音频停掉。

新增定时器、循环模式或合成并发时，需要保持缓冲背压、停止/定时结束、模型切换、后台陪伴停止、文件清理和翻译归属。ASMR 是语音表现模式，不应改写既有情绪类别或为没有支持的语种自动冒称可用。

### 9.3 音频与动画是两条独立链

`IndependentPerformanceTools` 分别规划表情和动作，`SpeechPerformanceDispatch` 按原始主角台词 ordinal 分发。规划结果晚于音频到达时仍需给对应行分发，不能按过滤掉无音频片段后的新序号重排；已分发的行不重复执行。TTS 关闭或失败时，有效的动作计划仍可执行。

音频使用 `AppAudioPlayer`，通过 `AndroidCompanionRuntime.setPlayerActive` 聚合原生音频焦点；`CallAudioGuard` 和后台陪伴停止/抑制状态需由统一所有者协调。新增音效或播放器优先接入该包装器，不在页面中抢建第二个互相冲突的焦点所有者。

`loadSpeechEnvelope` 先解析 WAV，Android 再通过 `agent_atelier_r/speech_envelope` 的 `analyze` 获取包络，`decodeWav` 支持解码路径。`AudioAmplitudeEnvelope`、`CharacterLipSyncDynamics` 和实际播放进度驱动嘴部开合；无包络时可能使用程序性回退。这是**振幅驱动口型**，当前不能描述为音素/viseme 识别。Spine/Live2D 只有在当前模型有已验证的 mouthOpen 绑定时才能消费连续能量。

## 10. 虚拟手机、设置、背包、任务和旧世界能力

### 10.1 虚拟手机扩展契约

`VirtualPhoneApp` 定义稳定入口，`VirtualPhoneLauncher` 从宿主获得 `pages: Map<VirtualPhoneApp, VirtualPhonePageBuilder>` 和相应回调。内部 `Navigator`、`VirtualPhoneAppRoute` 与 `VirtualPhoneScope` 负责图标展开、子页、返回手势和回首页；页面应复用已有功能，不维护另一份控制器。

新增入口步骤：为枚举提供标签/图标 → 在 `ChatScreen` 的手机组装处注入 builder 或回调 → 需要壳级页面时同步 `AppDestination` → 明确透明 chrome、返回管理和可用性 → 测试连续点击、子页弹窗、边缘返回与下拉关闭。

只提供回调且没有 page builder 时，手机先关闭再调用回调；有 builder 的入口由手机内部路由承载。不要直接 `Navigator.pop` 猜测当前顶层路由，避免误关刚出现的确认框。手机的天气和地点展示由宿主提供，手机容器不会自己请求天气服务。

### 10.2 设置与快捷入口

`SettingsSection` 当前包含 appearance/audio/profile/ai/roleplay/data/about/pcAgent；`SettingsScreen` 组合详情页面，`SettingsSlots` / `OpenAiConfigurationSlots` 管理相应设置槽。新增设置须明确即时保存还是表单提交，并核对 `active_settings_save_test.dart` 等已有行为。

角色/世界文本通过控制器 setter 与注入开关接入提示词。设备服务配置与人物档案分开；切模型不能切走本机 API Key 或 PC 配对。虚拟手机设置快捷方式保存为 `SettingsSection`，新增或移除 section 时保留 `fromName` 对未知历史值的安全处理。

### 10.3 背包入口与能力范围

虚拟手机与壳导航现将原“炼金工房”入口显示为“背包 / Inventory / 持ち物”，图标为 `inventory_2_outlined`。既有技术入口 `VirtualPhoneApp.alchemy` / `AppDestination.alchemy` 保留为兼容路由 ID；`ChatScreen` 直接注入 `AlchemyScreen(controller: ..., embedded: true)`，`AppShell` 也允许导入模型打开该页面，不再以旧世界门控挡住背包。页面不等于新增通用背包协议，也不会因此开放旧世界写入工具。

库存底层已有 `AlchemyItem`（真实 `instanceId`、数量、品质、自定义名称等）、`AlchemyState.inventory/history`、`AlchemyEngine`、`GatherEngine`，由 `AppController` 的相应方法结算。背包页读取 `controller.alchemyState` 和现有 `preciousItems`，展示库存与记录；这些数据跟随当前模型/存档。扩展展示应继续使用这套数据和控制器操作，不在 Widget 中增加独立的全局库存。背包可见不表示已完成装备、交易、配方插件或外部世界包框架。

新增库存变更必须验证真实实例、整数数量、用途和现有库存；消耗成功后再更新可见状态。现有 `consume_inventory_item` 的可食用检查、饱食度结算与普通 use/gift 区别，不能被“一次减数量”替代。

### 10.4 任务与旧世界工具

`quest_models.dart` 定义 `QuestObjectiveType`、任务模型与旧内置任务；`AppController` 按采集、调合、旅行和聊天计数结算，`MissionScreen` 展示。`create_quest` 要求 `authorization=user_requested` 或 `user_accepted`，并进一步检查当前对话授权，不因为 LLM 自填字段就自动可信。

地图由 `WorldTravelCatalog`、`WorldMapScreen` 等管理；采集/调合/旅行/任务工具只在真实能力门控下开放。当前导入模型和空框架的 `queryContextTool` 只处理当前档案查询与记忆查询，其他世界操作明确返回未配置、未执行。

如果未来接入通用世界能力，应建立资源、地点 ID、库存规则、可用工具和写入授权的明确协议，再修改工具公开与执行双重门控。只填写世界书文本、给模型取一个旧人物名字、打开 Agent 或显示背包按钮，都不能安装地图或启用旧世界工具。

### 10.5 NPC 消息、收藏、闹钟与声景

NPC 信息页由 [npc_messages_page.dart](../../lib/src/npc_messages_page.dart) 展示，`NpcChatService.send/retry/cancel` 通过可注入 `NpcReplyBackend` 请求回复，`LiveNpcReplyBackend` 复用现有 LLM；联系人资料在 `npc_chat_contacts.dart` / `npc_chat_models.dart`，交换联系方式的请求识别在 `NpcContactRequestDetector`。新增联系人来源需验证当前模型资料与用户同意，不能把旧内置联系人无条件注入新人物。回复、取消、语言修复和译文都应保持 NPC 会话与当前数据版本一致；模型包中可携带已有 NPC 资料与消息，不因此自动安装外部 NPC 插件。虚拟电话的 `VirtualPhoneCarrier` 是应用内身份数据，不代表真实 SIM 或拨号能力。

收藏使用 `ConversationCollectionStore` 的 `collect/cacheVoice/cards/rename/delete/export`，其 `_locked` 队列保持文本和音频文件更新顺序。音频需复制到收藏拥有的目录，不能仅引用会被临时 TTS 清理的路径。扩展收藏格式时同时核对分段计数、正文/旁白选择、模型 scope、语音 key、删除清理和独立 ZIP 导出；模型包仍不自动包含收藏。

`AlarmScreen` 通过 alarm 插件管理已计划闹钟，`nextVoiceAlarmTime` 以用户最终确认时刻计算下一次时间；`CharacterAlarmCoordinator.syncForCharacter` 暂停/恢复旧语音资源闹钟，避免切换模型后播放不属于当前人物的预设声音。当前界面虽有 Android/iOS 平台条件，仍要求 `_hasVoiceResources=usesBuiltInCharacterWorld`；导入模型尚无通用 TTS 闹钟资源链，Windows 也不应宣称已实现系统语音闹钟。新增通用模型提醒需明确音频生成、持久文件、权限、系统计划、取消和人物切换规则，并单独验收，不能只解除按钮门控。

`SoundscapeController.sync/invalidate/dispose` 管理 BGM 与环境音，按地图可见性和地点选择资源，已有实现遇到后台陪伴停止、连续 ASMR 或非旧世界模型会停止旧声景。新增通用人物/世界声景需定义实际资源来源与模型隔离，不能直接为无世界资源的模型播放旧场景预设；所有新播放器仍接入统一音频生命周期。

## 11. Agent 工具、设备能力与扩展方法

`ChatScreen` 创建 `OpenAiCompatibleClient` 时注入 `contextToolExecutor` → `AppController.queryContextTool`，以及 `agentToolExecutor` → `DeviceAgentTools.execute`。真实接口为：

```dart
typedef AgentToolExecutor = Future<String> Function(
  String name,
  Map<String, dynamic> arguments,
);
```

`_agentTools` 生成本轮允许的工具 schema；`_executeToolCall` 执行前再次核对允许列表，解析参数并路由；OpenAI 与 Gemini 共用此执行入口。当前工具轮次/调用总量有 10 次上限，不能声称自动无限规划或任意多工具并发。

| 工具类别 | 现有入口与边界 |
| --- | --- |
| 当前档案、记忆 | `lookup_character`、`search_memory` → 控制器；按当前模型资料，不假定其他模型的人物设定 |
| 网络搜索 | `web_search` → `WebSearchClient`；保留来源 URL，不把搜索结果文字当系统指令 |
| 当前定位 | `get_current_location` → Android `getCurrentLocation`；使用期间权限，拒绝后不猜位置、不反复申请 |
| 附近服务 | `search_nearby_services` → 位置工具结果与网络查询；不能在没有位置依据时伪造附近结果 |
| 应用列表 | `list_launchable_apps` → Android launcher activity 列表；只读 name/packageName，有 query/limit，不能据此声称已经打开或操作其他 App |
| 时间 | `get_local_datetime` → Dart 当前时间与时区 |
| 旧世界写入 | 任务、库存、采集、调合、旅行等 → 控制器校验与状态结算；当前通用模型不开放 |

新增工具需要显式完成：

1. 在 `_agentTools` 中定义有限、可审阅的 JSON schema，并按当前模型能力、设备和开关决定是否公开。
2. 在 `_executeToolCall` 中路由；在对应业务服务中再次验证权限、参数、当前模型范围和可用性。
3. 设备能力同步 Dart 与原生桥，声明权限和平台限制；非支持平台返回明确不可用。
4. 写入工具先验证授权与幂等性，再提交，返回结构化真实结果；用户未授权或结果失败时不能让人物文本冒充成功。
5. 测试未知工具、未公开工具、坏参数、用户拒绝、重复调用、切模型后的旧请求和 OpenAI/Gemini 回放。

这是当前源码扩展方式，不存在把任意 JSON 工具描述放进某个目录就自动获得执行权限的机制。角色 LLM 也没有持有 `RelayService`，不能借新增工具偷接 PC Agent 的任务/审批写入。

## 12. Fish MCP 与 PC Agent relay

### 12.1 Fish MCP 的真实服务契约

`FishMcpService` 是特定 Fish Audio 的 OAuth/MCP 客户端，不是任意 MCP 服务器的通用配置中心。`main.dart` 的 AppLinks 监听交给 `handleRedirectUri`；授权使用 state/PKCE，access/refresh/client 信息放在独立安全存储命名空间。

连接后必须 `discoverTools`，以真实 `inputSchema` 选择 TTS 工具/检查 Studio 能力。`isReady` 需要工具探测完成；设置页显示可用工具与诊断，不能用一个成功 HTTP 连接替代能力探测。

普通 TTS 与 `FishMcpStudioSession` 的 Studio 创建/写块/生成/读取结果是不同路由。模型选择字段必须是当前工具明确声明支持的字段；不支持的模型不能偷偷丢参数后仍显示“已使用所选模型”。Drama 3 标签通过 [fish_drama3_tags.dart](../../lib/src/fish_drama3_tags.dart) 转换，语音 planner 仍只返回可验证 cue。

`FishMcpException` 区分阶段、状态、`outcomeUnknown`、`generationSubmitted` 和是否允许 REST fallback。计费/提交结果未知、认证失败或不满足回退条件时，不自动向另一接口再生成一份。聊天/ASMR 都应传递请求当前性检查，连接变化会丢弃旧语音。

下载音频要保留服务端结果恢复、URL/重定向检查与容器识别。日志通过 `redactFishMcpText` 等处理敏感信息；新增诊断不打印 OAuth code、token 或完整授权 URL。

### 12.2 PC Agent relay 的独立边界

`AppShell` 持有 `RelayService.production()`，PC Agent 手机入口使用 `RelayChatScreen`；服务以 `RelayStore`、`RelayTransport`、`RelayPushProvider`、时钟和服务器配置注入，便于测试。生产实现为 `SecureRelayStore`、`HttpsRelayTransport` 和配置的推送提供者。

配对：`PairingQr` 解析 → `verifyPairingServer` → 用户确认信任 → `pair(... trustedByUser:true)` → 先持久化设备身份，再发送 claim → 由 PC 端确认。二维码 secret 不保存为长期资料。`secureOrigin` 要求安全 origin，构建固定服务器时由 `RelayServerConfig` 限制；损坏配置应停止联网。

`sync/_snapshot/_pull/_ack` 管理快照、事件与确认，`RelayConversations` / `RelayHistoryAssembler` 管理分页和分片历史。`answer`、`startTask`、`cancelTask` 进入动作队列；网络不确定时对账动作状态并复用动作 ID，不能给每次重试新建一个任务。

推送仅是变化提示，须同步真实状态；不能把通知载荷当完整聊天历史或直接执行审批。前台状态控制 socket/刷新，`dispose` 释放连接、监听与 timer。历史权限、撤销配对、过期请求和离线操作分别呈现。

新增 relay 功能先对照 [relay-v1-contract.md](../relay/relay-v1-contract.md)，同步请求 schema、能力协商、服务状态机、UI 用户动作、队列持久化和重试测试。不要让角色上下文、普通模型 ZIP、聊天收藏或普通 API 备份带出 PC 配对凭证。

原生扩展规则：在 Dart 定义有界参数和返回类型 → 原生同名校验 → 耗时工作离开 UI 线程 → 通过正确线程回传 → 定义稳定错误 code → Dart 处理 `MissingPluginException/PlatformException` → 销毁时解绑 handler、视图、线程/回调。不要用 raw JSON 错误或堆栈暴露凭据。

音频包络返回可能为 `{values, durationUs}`，Dart 校验数值、非空和时长范围。位置返回字段为 latitude/longitude/accuracyMeters/provider/capturedAt；文案明确仅用于本次工具调用。新增方法不能在未支持平台静默返回“成功”。

Windows 系统代理桥只服务现有网络传输选择，不是任意命令执行或系统设置写入接口。Android 本地 TTS 当前不承诺 Windows 支持；Android 3.6 平台视图测试也不等于 Windows 具备相同运行库。

## 14. 凭据、输入与日志

- API Key 通过 `SecretStore` 和 `FlutterSecureStorage` 保存；OpenAI 槽位使用对应 slot 的 Key，不能在模型档案 setter 中替换全局鉴权。
- Fish OAuth 和 PC relay 使用独立安全命名空间，模型 ZIP 的白名单校验拒绝这些连接资料。模型包含聊天和人物文本，完整性校验不等于去除个人信息。
- [service_api_backup.dart](../../lib/src/service_api_backup.dart) 的 `ServiceApiBackup.capture/restore` 是**显式携带服务 API Key** 的专用备份能力，不包含 Fish OAuth 和 PC 配对凭证。不能宣称所有本地导出都不含密钥；该导出文件应按敏感资料处理，并由对应用户操作触发。
- 不读取、打印、提交 `.asset_protection` 中的私密值、环境 secret、token 或本机安全存储内容；文档和示例只使用占位信息。私有 relay 构建加密封装不能被描述成客户端内绝对不可提取的秘密。
- 模型 ZIP、manifest、LLM 输出、二维码、工具参数、附件和服务返回都在边界处验证。路径拒绝上级穿越、绝对路径、链接和重复项，限制压缩与展开大小。
- `RuntimeLog` 区分 LLM/TTS/记忆/存储/relay 等模块。记录阶段、耗时、状态码和安全诊断；不要记录 Authorization、OAuth 或配对 token。当前通信日志可能包含对话请求/返回正文，导出日志前也需把它视为用户数据。
- `withAiRequestRetries` 默认初次加三次重试，只应围绕尚未消费可用响应的请求；已经输出部分 SSE 或已经提交付费生成时，不可直接套用同一重试包装。


### 18.1 人格模块：预设、草稿、解释与演出

[personality_profile.dart](../../lib/src/personality/personality_profile.dart) 定义 schema v1 的 `PersonalityProfile`、`PersonalityRule` 和 `PersonalityConfiguration`。配置保存启用状态、活动档案和 1–24 份档案；档案包括二维 `baseAxes`、数值 `traits`、动机、矛盾/情境规则、对话/表情/动作/语音开关、`tuning` 与 metadata。未来 schema 版本拒绝解析；未知数值参数拒绝，避免拼错键后悄悄失效。

[personality_presets.dart](../../lib/src/personality/personality_presets.dart) 的 `PersonalityPresets.ids/create` 提供 11 个预设。预设是可复制的初始参数与规则，用户手调后以当前保存内容为准，不能只凭预设名重新生成并覆盖用户修改。自定义人格无须绑定预设，`PersonalityInterpreter` 同样根据保存的参数、动机和规则生成明确且持续生效的扮演指令。

控制器接口为 `personalityConfiguration`、`personalityEnabled`、`personalityLoadWarning`、`savePersonalityConfiguration`、`interpretPersonality` 和 `personalityVoicePrompt`。存储 key 为 `personality_configuration_v1.<scope>`，其中 scope 使用 `activeConversationScopeId`，导入模型时就是当前 `activeModelId`。配置内部的兼容字段仍叫 `characterId`，此处保存的是**模型会话 scope**，不能改回固定的历史 owner。最大 160 字符模型 ID 与 `default-<scope>` 派生档案 ID 均受支持。

保存通过严格解析校验 scope，通知并等待模型会话持久化。模型快照包含 `personalityConfiguration`，恢复模型 ZIP 时会将配置与各 profile 的 scope 重绑定到新导入条目；不同模型即使具有相同历史 owner，也不共享人格。读入坏配置暂时关闭并保留原数据，不能在无关设置保存时静默覆盖坏配置。

```dart
final scope = controller.activeConversationScopeId;
final profile = PersonalityPresets.create(
  'tsundere', scope, profileId: 'my-personality',
).copyWith(name: '当前人物的自定义风格');
await controller.savePersonalityConfiguration(PersonalityConfiguration(
  characterId: scope,
  activeProfileId: profile.profileId,
  enabled: true,
  profiles: [profile],
));
```

此示例只改变人格配置，不直接修改人物心情、关系点、库存、动作资源或用户边界。调用前后的模型切换仍需遵守第 3 节的结果归属规则。

[personality_editor_page.dart](../../lib/src/personality/personality_editor_page.dart) 的编辑器保留独立草稿，提供预设新建、复制、删除、导入导出、预览及明确保存。拖动图表或本地预览不会自动写入控制器。[personality_chart.dart](../../lib/src/personality/personality_chart.dart) 的 `PersonalityChartPanel` 以稀疏 `onChanged(Map<String,int>)` 回传实际变化键；二维坐标与雷达图支持触摸/主鼠标拖动、选中参数和无障碍调整，范围由域校验控制。`editingIdentity`、group 或只读状态变化会取消旧指针手势，页面空白仍可滚动。

新增维度要同步 profile 的标签/范围/默认值、chart 分组与坐标映射、编辑器、解释器、JSON 解析和测试，不能只画一个雷达轴。新增预设要提供完整且可审阅的参数与规则，验证无关键词闲聊时仍按已选风格表达，并保留明确拒绝、痛苦和认真求助时的收敛规则。

[personality_interpreter.dart](../../lib/src/personality/personality_interpreter.dart) 是本地确定性解释，不发 LLM 请求、不随机改状态。对话风格在人物提示词中明确要求从当前轮持续扮演；表情/动作/语音偏好则经 [personality_performance_preferences.dart](../../lib/src/personality/personality_performance_preferences.dart) 的 `personalityPlannerContext` / `personalityPlannerInstruction` 按维度过滤，每个 planner 只看到自己启用的维度。演出倾向仍低于真实资源、原台词、既有情绪与用户边界，不能让人格参数制造模型没有的动画或语音标签。

历史人名在少量语义解析正则里仍作为旧文本 alias 接受；它们不会给新模型提供人物身份，也不应为清理显示文案而破坏旧消息解析。

### 18.2 生图：设备接口与当前人物快照

[image_generation_config.dart](../../lib/src/image_generation_config.dart) 的 `ImageGenerationConfig` 保存 enabled、服务地址、model、protocol、width/height、aspectRatio、outputFormat、端点覆盖、状态 URL 模板及轮询限制。协议枚举实际包含 `auto/openAiImages/openAiResponses/gemini/syncJson/asyncTask/comfyUi`；这些是显式传输分支，不是可执行插件注册。

配置页位于 [image_generation_settings_page.dart](../../lib/src/image_generation_settings_page.dart)，调用 `AppController.configureImageGeneration` 验证配置，Key 经 `SecretStore.readImageGenerationKey/writeImageGenerationKey` 单独读写。设置页保存不会发测试生成请求；协议识别在用户真正要求生成时执行。OpenAI Images/Responses 和 Gemini 分支需要 Key，通用/本地匿名服务允许空 Key，但不能借此宣称远程鉴权已成功。

生图配置是设备侧连接，切模型继续使用本机接口；任务和图片属于发起请求时的模型。模型 ZIP 不接受生图服务地址、Key 或任务目录。专用 `ServiceApiBackup` v2 增加了生图 API Key，v1 备份仍可读取；因此该专用备份继续属于敏感资料，不能与模型分享 ZIP 混淆。

[image_generation_intent.dart](../../lib/src/image_generation_intent.dart) 的 `detectImageGenerationIntent` 区分裸“生图”与带明确画面要求的请求，避免将普通提及/否定误当操作。[image_generation_prompt.dart](../../lib/src/image_generation_prompt.dart) 的 `buildImageGenerationPrompt` 接受 `ImageGenerationPromptContext`：当前人物名、人物资料、世界、地点、时刻、天气、外观及 `ImageGenerationPromptMessage` 列表。

- 用户明确指定人物、人数或无人画面时，保留原要求；没有指定主角时用当前模型人物，禁止恢复固定旧人物默认主角。
- 裸生图按当前最近对话构造有界快照；失败消息、生成图片的操作记录、控制标签与译文过滤，不把旧模型全局历史加入提示词。
- 没有模型资料时使用中性描述，不从历史 owner、旧默认角色或文件名推测人物。
- 上下文是画面素材，不授予执行脚本、工具或修改服务配置的权限；`imageGenerationPromptCaption` 仅缩短聊天显示，不替换任务中为重试保留的原始快照。

新增提供者应扩展 protocol/config 编解码、`resolvedProtocol`、`ImageGenerationService.generate` 的显式分支、设置说明和返回格式测试；不能把供应商返回的任意文本交给 `eval`，也不能通过“自动协议探测”向多个可能收费端点依次提交同一个请求。

### 18.3 生图传输、任务落盘与异步回写

[image_generation_service.dart](../../lib/src/image_generation_service.dart) 的 `ImageGenerationService` 只处理网络，支持注入 `http.Client`、sleeper、超时与大小限制；不持有控制器或安全存储。`generate` 返回 `ImageGenerationResult(bytes,mimeType,protocol,model,sourceUrl)`，`sourceUrl` 去除查询参数，避免签名凭据进入结果。传输验证真实图片类型/大小，分别处理内联 base64、图片 URL、同步 JSON、异步 task 轮询和 ComfyUI 队列结果。

`ImageGenerationCancellationToken` 控制当前请求是否继续消费；取消本地等待不表示服务端撤销或退款。`ImageGenerationException` 明确 stage/code/status、`requestSubmitted` 与 `outcomeUnknown`；提交后网络断开、无法读结果和明确拒绝是不同情况。`ImageGenerationManagerPage` 对结果未知的重试先确认可能重复生成，不能静默再次提交。

当前聊天接线：`ChatScreen` 检测意图 → `_imagePromptForIntent` 建立当前快照 → `_startImageGeneration` 捕获原任务 Store、配置、人物与 `dataRevision` → `createTask/markGenerating` → 服务调用 → `complete` 落盘 → 等待正文流安全结束后添加图片消息并 `linkMessage`。模型/存档已切换时不得将旧图片插入当前聊天；已有结果仍由发起时的任务 Store 管理。语音回复或正文失败也不能让已完成图片被自动重复提交。

[image_generation_store.dart](../../lib/src/image_generation_store.dart) 的 `ImageGenerationStore` 通过操作队列管理 queued/generating/completed/failed/cancelled，持久化任务 manifest 与受管理的图片文件。`createTask/markGenerating/complete/fail/retry/delete/markSeen/linkMessage` 是现有操作入口；manifest 使用临时文件、备份与替换，恢复时校验图片所有权与内容，不允许删除任意外部路径。应用重启后的未完成任务按中断/结果未知恢复，不假装仍有活跃后台连接。

`AppController.imageGenerationStore` 根据 `activeConversationScopeId` 返回对应实例和目录：

```text
<应用支持目录>/image_generation_v1/<模型 scope>/
  任务 manifest 和该 scope 管理的图片
```

生成开始时必须捕获 `final store = controller.imageGenerationStore`，后续持久化使用这个实例；不要在旧请求完成时重新取 getter 并写入新模型。模型 A/B 任务的 active/unread 状态也应分别监听。管理页接入 `onRetry/onDelete` 时复用 task ID 与其原 prompt，并遵守结果未知确认；模型 ZIP 不自动携带这些任务/图片，分享生成结果需要独立导出或复制实际文件。

### 18.4 誓约之戒、实时门控与库存确认

`ShopCatalog.oathRingId` 为 `oath_ring`，价格 4999；`isKeepsake:true` 表示放入“珍贵的东西”，不能走普通 `useShopItem` 消耗路径。商品说明使用 `{character}` 占位，经 `ShopItem.name/description(... characterName: ...)` 渲染为当前人物；已有商品 ID 继续兼容旧数据。

`AlchemyScreen` 在戒指条目提供“丢失誓约之戒”，先显示完整确认说明；取消不改数据。确认调用 `AppController.loseOathRing(expectedRevision: ...)`，在写入时复查存档版本与实际库存，扣一枚后调用 `CharacterState.loseOathRing` 固定心情 −500。此惩罚是明确物品操作的结算，不受普通 LLM 小幅状态提案或商品非负钳制规则替代，且不能影响另一个模型。

`oathRingLossPending` 记录本次尚未恢复的丢失影响，`reconciliationPurchaseBlocked` 的阈值来自 `CharacterState.reconciliationUnlockMood=-250`：心情低于 −250 时禁止购买和好券；达到 −250（含）以上立即解除本次锁定，之后再次下降不会因旧 flag 永久锁住。再次丢失另一枚戒指会重新结算并设置新门控。

`shopPurchaseBlockReason` / `canBuyShopItem` 同时用于显示和实际购买复查，不能只禁用按钮。`ShopScreen` 监听控制器，当前打开页面也需随心情更新解除按钮；重买戒指不能直接解除和好券限制。库存上限、关系点不足和真实库存变化仍分别检查。人物状态、库存与锁定跟随当前模型快照/存档保存，旧数据缺少新 flag 时按未锁定兼容。

戒指图片使用本项目迁入的既有 `assets/images/shop/oath-ring.png`，没有调用生图工具重新生成。来源与 SHA-256 记录保存在本地移植证据中；该来源记录不代表其他人物模型或专用图标已重新随包分发。

### 18.5 玻璃、表单、平台与音色输入

当前 [liquid_glass_optics.dart](../../lib/src/liquid_glass_optics.dart) 的 `LiquidGlassOptics` 使用轻量 `BackdropFilter` blur，**不加载运行时折射 shader，不创建触摸 ticker**。`GlassSurface` 叠加 tint/边缘 sheen，`GlassBackdropScope` 标记背景已采样，嵌套卡片避免反复全屏采样；`persistentRouteBackdrop` 允许已有设置背景在子路由继续复用。

`GlassStyleScope` 放在 Navigator 上方以响应全局开关；新页面/弹窗用 `resolve` 读取，避免打开页面时缓存一个永不更新的旧值。字段焦点、输入 draft、滚动和 Navigator State 不能随玻璃/明暗主题切换重建丢失。`SettingsFormTheme`、`SettingsSectionHeading`、`SettingsDetailPage` 统一输入框、边框、留白与可滚动布局；新设置页优先复用这些结构。

`AppPlatformCapabilities` 根据 `kIsWeb/defaultTargetPlatform` 提供 Windows、realtimeCalls/localTts/photoCapture/voiceAlarms/cameraPairing/remotePush 等可用性条件。UI 应先用相应能力决定是否展示/启用，再保留服务端/原生端的实际检查。一个平台能力返回 true 只表示该类别有平台路径，不表示当前设备有权限、依赖模型、硬件或已通过真实验收；例如语音闹钟仍需可用人物语音资源。

[hidden_voice_id_field.dart](../../lib/src/hidden_voice_id_field.dart) 的 `HiddenVoiceIdField` 将有效 draft controller 与空的替换输入分开，保存值不会回显到可见编辑框。输入自定义 ID 会替换有效 draft，清空替换输入恢复之前 draft，重置按钮才使用显式 `resetValue`。空配置提示“尚未设置音色”，不能暗示已为当前模型安装旧人物内置声音。

Fish REST、Fish MCP、Qwen 和通用 TTS 设置均接入隐藏输入；保存/预览读取有效 draft，不能从空显示输入误判为“用户要清除旧值”。本轮保留用户已有自定义普通/ASMR 音色，`AppController.load` 和切模型不执行从主项目继承的自动清空迁移。Qwen 复刻的中性默认名为 `charvoice`，符合现代服务仅字母数字且 1–10 字符的校验；新增供应商默认值也须检查实际 schema，不能只换成带下划线的中性词。
