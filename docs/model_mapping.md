# 模型导入映射

动作映射和聊天人物设定分别处理，并共同归属于当前模型的档案。每次导入人物资源，先在本地扫描资源目录，再调用当前配置的 LLM 生成语义映射，检查并确认后才保存模型。映射不作为聊天消息或长期记忆写入。模型与应用数据的保存方式见 [模型档案与独立数据](model_workspaces.md)。

## 操作

1. 在设置中配置并启用 AI 接口。
2. 在模型库的导入入口选择 Spine 或 Live2D；也可从「设置 → 模型档案与数据」进入。
3. 选择模型 ZIP。应用先显示格式、运行库兼容情况和动作、表情、参数等资源数量。
4. 点击「使用 LLM 生成映射」。调用使用当前 AI 服务、模型与安全存储的 API Key，可能产生该服务的调用费用。
5. 检查每项的动作说明、资源名称、依据与置信度。展开「编辑映射 JSON」可以修改或删除绑定；错误资源引用会阻止导入。
6. 点击「确认映射并导入」。随后在模型库选择模型，动作页显示已绑定的能力。

场景、座椅和替换贴图继续走各自的导入流程。已有本地模型保留原控制方式。

精确匹配原有 Spine 模板的模型在分析后可选择「保留完整操纵模板」，默认开启，以保留原有动作组合和驱动；AI 映射另行保存。取消此选项才改用通用控制器。程序同时检查实际骨架包含模板需要的基础动画，不按近似文件名套用模板。

## 支持范围

| 格式 | 资源扫描与 LLM 映射 | 当前播放 |
| --- | --- | --- |
| Spine 4.2 JSON / binary | 动画、时长、骨骼、槽位、皮肤、约束等目录 | 原生 Spine 4.2；通用映射使用独立待机、动作、整脸表情与口型轨道 |
| Spine 3.6 JSON | 动画、骨骼、槽位、皮肤等目录 | Android 使用离线 Spine 3.6 WebGL 运行库，支持待机、动作、表情、口型与暂停恢复；其他平台暂不开放导入 |
| Live2D Cubism model3 | 动作组、动作、表情、已声明参数及已有 manifest | 现有 Cubism 播放端，使用生成的 performance.manifest.json |
| VRM 0.x / 1.0 | 读取 humanoid、表情等扩展并生成映射 | 尚无 VRM 渲染器，显示兼容提示并禁用导入 |

资源名称不足以证明动作含义时，LLM 应省略绑定并说明缺少的依据。编号动作不自动被当作拍手、抱臂或其他明确姿态。目录校验能证明资源存在，无法证明某个动作的视觉含义完全正确，仍需用户检查实际播放。

## 映射协议与扩展

`ModelResourceCatalog` 为所有格式提供稳定的资源 ID、格式、入口、运行库版本、完整源文件 SHA-256 和兼容信息。后续新增渲染器时，复用目录与映射协议，增加对应的资源扫描和播放适配即可。

`ModelPerformanceMapping` schema v1 保存 `sourceFingerprint`、`format`、`label`、`idle`、`actions`、`expressions`、`parameters`、`notes`。绑定包含 `target`、`description`、`confidence`、`evidence`。Spine 必须选择实际存在的待机动画，所有引用均根据本次扫描目录校验。

Spine 的程序桥接生成 gesture 中的 `ModelMapping.Runtime`，真实资源名由程序从目录解析；通用模型使用 `generic_spine` 播放器。Live2D 桥接生成 `performance.manifest.json`，选定的待机会在动作完成后恢复。完整语义映射另存为 `performance.mapping.json`，与角色模型放在应用私有目录中；源指纹在添加这些派生文件之前计算。

当前通用播放器执行待机、单个主要动作、表情及有可靠范围证据的口型绑定；其他参数角色先记录在映射中，供后续视线、呼吸等控制器接入。Spine 普通循环说话动画不会冒充按音量驱动的 0..1 嘴部开合。新通用模型不套用莱莎专用的骨骼偏移、触摸物理或动作组合；旧模型继续使用原控制器。

LLM 不执行脚本，不修改骨架版本，不新增网格或动画，不安装运行库。只发送资源目录与必要的结构摘要，不发送贴图、完整网格、聊天记录或长期记忆。资源包中的文字都视作待分析数据。请求失败不会自动反复调用；用户可检查配置后自行重试。

目录超出提示词预算时会明确报错，不静默删除后半部分资源。模型文件继续由用户自行导入，不随应用安装包分发。
