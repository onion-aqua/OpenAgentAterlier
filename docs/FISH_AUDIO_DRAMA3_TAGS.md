# MCP Drama 3 标签适配

依据 2026-10-18 查阅的 [Fish Audio Drama 3 官方开发文档](https://docs.fish.audio/features/text-to-speech/drama-3) 实现。

设置 → 声音 → Fish Audio MCP 中选择 `drama-3` 后，实际发送的语音文本使用官方局部成对标签：

| 标签 | 用途 |
| --- | --- |
| `<whisper>…</whisper>` | 耳语 |
| `<emphasis>…</emphasis>` | 强调 |
| `<soft>…</soft>` | 轻柔 |
| `<fast>…</fast>` | 加快 |
| `<slow>…</slow>` | 放慢 |
| `<stress>…</stress>` | 重读 |
| `<forceful>…</forceful>` | 强势发声 |

这些标记属于语音文本，不是 MCP 工具的新参数。显式模型继续使用现有已确认的 Studio `default_backend` 配置路径。

## 应用行为

- 语音规划器按 Drama 3 支持的发声类型选择必要标签，遵守情感强度与标签密度设置。标签关闭时不会自动增加耳语。
- 内部仍使用通用方括号语义标记，在 MCP 合成边界统一编译，避免尖括号影响分句、翻译、存档显示与记忆。新语义标记也会从记忆文本中清除。
- 耳语、轻柔和语速作用于后续台词，遇到新的发声控制切换；强调、重读和强势发声限定下一短语，避免整段长篇都被强调。
- 普通方括号情绪方向和短停顿仍然有效。官方允许自然语言方向，但本应用继续清理过量喘息、吸气、呼气和叹气标签。
- 默认模型、S2.1 Pro 与独立 Fish Audio API 配置沿用现有标签格式。MCP 的 REST 回退使用转换前文本，不把新的配对格式误传给其他配置。
- 请求诊断中的 `speech_tag_format` 标记为 `drama3_paired`，用于核对本次请求是否选择了此分支。不增加生成次数或失败后的付费重试。

示例：内部 `[sad][whispering]大丈夫。` 在 Drama 3 请求中发送为 `[sad]<whisper>大丈夫。</whisper>`。

## 官方能力与验证范围

官方还提供实验性语言切换、音素以及多说话人控制。本次只使用上述七种明确列出的发声标签；不会自动添加实验性语言切换、音素、SSML 或新说话人。

官方文档说明语音文本方向在 API 与网页中一致，MCP 文档确认可在 `text` 中传递语音方向，但未单独公开每个 Studio 工具的成对标签执行保证。离线测试已确认标签正确进入 MCP Studio 文本块；没有调用收费语音生成，实际云端听感仍待试听。
