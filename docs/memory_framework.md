# 记忆框架说明

当前记忆实现参考了 [SillyTavern-Horae](https://github.com/SenriYuki/SillyTavern-Horae) 的几个核心思想：把记忆当作可追加的事件账本，把当前状态视为事件回放后的投影，并把摘要当作可重建的压缩视图。项目没有复制 Horae 的扩展协议或浏览器存储实现，角色、存档和用户编辑仍沿用本项目的数据模型。

## 写入路径

每轮完整回复落盘后，`MemoryLedger` 会在本机做一次保守的事实提取。它只识别明确确认的约定、物品、地点、关系变化和用户偏好，并记录类别、关键词、重要度、来源消息 ID、来源角色、观察时间和置信度。问句、未接受的请求、假设和单独的瞬时情绪不作为长期事实；例如日语“喜欢书”不等于关系转折。它会遍历一轮中的所有句子，同一句命中多种类别时只保留一项；`<think>`、`<tool_call>`、`<function_call>`、`<horae>` 等内部块不会进入事实，`<answer>` 和 `<code>` 标签本身会被移除。已知的表情、重音和动作控制标签会移除，普通方括号内容保留。

本地事实通过 `MemoryTimeline.normalizeCandidate` 作为增量候选追加到已有时间线。已有条目、用户手动修改和用户删除形成的序列空洞优先级更高；模型候选不能覆盖它们。演示回复也走同一条本地写入路径，因此没有 LLM 时仍能保存高置信事实。取消、失败或半截流式回复不会写入账本。

模型整理仍然用于最近记忆和长期记忆的语言压缩，但它只能提交新增事件。`applyConsolidatedLongTermMemory` 会检查编辑版本、最近记忆游标和条目数量，拒绝把完整时间线压缩成一条或清空旧记忆的结果。整理请求失败时保留现有长期记忆、最近记忆和游标。

本地记录以人物归属及事实类别说明来源，使用 `local_ledger_version=2` 区分新的提取规则。模型摘要跟随界面语言，使用第三方视角而非角色台词。整理提示词要求尽量在50字内概括，程序保留完整句子；超过400字的异常生成结果拒绝保存，不再截成半句。

## 修复旧版本的台词式记忆

打开“记忆”页，点击“马上整理”。旧版本的本地记录会用关联消息 ID 查找原始对话，重新生成摘要；原始对话已不在当前历史时只概括现存片段，不补全丢失情节。确认页会标明重新整理的条目和补译文条目，允许编辑后保存。取消或请求失败不改变已有记忆。

已有条目缺少译文时，即使没有新对话也可以补译文。修改摘要或原始 JSON 的用户编辑会标记为 `source=manual`，后续整理保护原文。确认保存一次性提交长期记忆、最近记忆及进度，任何校验失败都不推进游标。自动整理仍只追加事实，只有用户确认的修复条目可以改写原有条目。

## 召回路径

生成角色提示词时，系统按以下顺序提供上下文：当前状态投影、未整理的最近记忆、与当前输入相关的长期事件。长期事件使用本地可解释评分：中文字符和二元组、英文词、类别、关键词、重要度、活动状态和时间序列共同参与排序。它不要求 embedding 模型或网络服务，低重要度但与当前问题相关的事实仍可以被召回。选中的事件保留原始序列顺序，便于模型理解时间变化。

## 存档与编辑

`memorySummary`、最近记忆、整理游标和编辑版本都随角色存档保存，创建新存档时会清空。导入旧版纯文本时会保留为 `legacy` 条目，再逐步追加结构化事件；旧文本不会被截断。记忆时间线显示 `AM0001` 一类编号；删除后显示编号重新连续排列，内部 `sequence` 空洞保留，以免自动整理把已删事件恢复。

## 后续扩展边界

当前实现没有在 APK 内置向量模型，也没有把模型生成的隐藏标签当作可信事件。后续可以在不改变账本格式的前提下增加本地 embedding、RRF 混合召回、分层摘要和 tombstone 事件；这些组件只能改善召回和压缩，不能替代本地事件保留及用户编辑保护。
